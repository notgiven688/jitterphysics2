Stabilize(float, int, int, bool)

Adjusts velocities to satisfy existing contacts and constraints without moving the bodies.

public void Stabilize(float dt, int solverIterations, int relaxationIterations = 0, bool multiThread = true)

Parameters

dt float

The reference timestep in seconds used to scale bias and softness terms.

solverIterations int

The number of solver iterations to execute.

relaxationIterations int

The number of relaxation iterations to execute after solving.

multiThread bool

If true, uses the internal thread pool for parallel execution. Multithreaded calls are internally serialized across all worlds because the worker pool is process-wide.

Remarks

Useful after restoring a saved scene, before resuming Step(float, bool). Only active contacts and constraints are solved. No new collisions are detected, forces are not applied, and positions and orientations are left unchanged.

Exceptions

ArgumentException

Thrown if dt is negative or not finite, solverIterations is less than 1, or relaxationIterations is negative.

Step(float, bool)

Performs a single simulation step.

public void Step(float dt, bool multiThread = true)

Parameters

dt float

The duration of time to simulate in seconds. Should remain fixed and not exceed 1/60 s.

multiThread bool

If true, uses the internal thread pool for parallel execution. Set to false for single-threaded execution (useful for debugging or platforms without threading).

Remarks

The step is divided into SubstepCount substeps for improved stability. Do not step or modify this world from another thread while this call is running. Multithreaded steps in different worlds wait for each other; single-threaded steps can run concurrently. Step and substep events run on the calling thread. Collision filters may run concurrently on worker threads when multiThread is true.

Exceptions

ArgumentException

Thrown if dt is negative or not finite.

Event Type

Action<Constraint>

Remarks

The event is raised for explicit removal as well as automatic removal caused by removing a body or clearing the world. It is not raised when a constraint is disabled, when a body's motion type changes, or when the world is disposed. The constraint is invalid when the callback runs, but its Body1 and Body2 references remain available.
